# Chat Local

Un mini-chat local en Python avec interface web, compatible avec plusieurs clients sur un même réseau local.

## Vue d'ensemble

Ce dépôt contient une application de chat locale qui permet :

- de connecter plusieurs utilisateurs sur le même réseau local
- de discuter en temps réel via Socket.IO
- d'utiliser une interface web moderne
- de lancer un client desktop Tkinter pour la même expérience

## Composants

### 1. Serveur web principal

Le serveur principal se trouve dans `server/app.py`.

- Flask + Socket.IO
- écoute sur `0.0.0.0`
- gestion des utilisateurs connectés
- émission des messages à tous les clients
- liste des utilisateurs en temps réel
- messages système sur connexion/déconnexion

### 2. Interface web

Le frontend se trouve dans `web_chat/templates/index.html` et `web_chat/static/`.

- modal pour choisir un pseudo
- design sombre moderne
- liste des utilisateurs
- messages envoyés et reçus
- responsive mobile

### 3. Client desktop

Le client GUI se trouve dans `desktop/client_gui.py`.

- interface Tkinter via `ttkbootstrap`
- connexion au serveur Socket.IO
- affichage des messages et de la liste des utilisateurs

## Pré-requis

- Python 3.10+
- pip

## Installation

```bash
python -m venv .venv
source .venv/bin/activate   # Linux/macOS
# ou .venv\Scripts\activate  # Windows
pip install -r requirements.txt
```

## Configuration

Copiez le fichier d’exemple puis ajustez les variables d’environnement :

```bash
cp .env.example .env
```

Exemple de `.env` :

```env
CHAT_HOST=0.0.0.0
CHAT_PORT=5000
CHAT_SECRET_KEY=change-me
CHAT_ALLOWED_ORIGINS=http://localhost:5000,http://127.0.0.1:5000
CHAT_SERVER_URL=http://127.0.0.1:5000
```

## Lancer le serveur

```bash
python server/app.py
```

Le serveur sera disponible sur :

- http://127.0.0.1:5000
- http://localhost:5000

## Lancer l’interface web

Ouvrez simplement :

```text
http://127.0.0.1:5000
```

## Lancer le client desktop

```bash
python desktop/client_gui.py
```

## Sécurité importante

Le dépôt ne doit jamais contenir :

- de clés SSH privées
- de secrets codés en dur
- des tokens dans le code
- des fichiers sensibles non chiffrés

Le fichier historique `eric` a été neutralisé et remplacé par un placeholder. Pour une vraie suppression complète dans l’historique Git, il faut réécrire l’historique du dépôt avec un outil de nettoyage comme `git filter-repo` ou BFG, puis forcer la publication d’une nouvelle branche ou d’un nouveau dépôt propre.

## Problèmes connus et améliorations prévues

### Axes de correction

1. Centraliser l’implémentation serveur.
2. Supprimer les secrets et les configurations codées en dur.
3. Vérifier les pseudos en doublon.
4. Ajouter des tests unitaires et fonctionnels.
5. Implémenter la persistance des messages.
6. Sécuriser les événements Socket.IO.
7. Ajouter un historique de conversation.
8. Éliminer les versions legacy devenues obsolètes.

## Plan de refactorisation recommandé

### Étape 1 – Nettoyage du dépôt

- retirer les secrets

- créer un fichier `.env.example`
- ajouter `.gitignore`

### Étape 2 – Consolidation serveur

- garder un seul serveur principal : `server/app.py`
- transformer `web_chat/app.py` en wrapper d’compatibilité
- supprimer les duplications

### Étape 3 – Sécurité et validation

- historique de chat

### Étape 5 – Tests automatisés

- tests de connexion

- tests de validation des pseudos

### Étape 6 – Production
